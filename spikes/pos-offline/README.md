# تجربة إثبات: نقطة بيع تعمل دون اتصال وتُصالِح دفتر الأستاذ بالضبط عند العودة
# Spike: an offline-capable POS that reconciles the ledger exactly on reconnect

> **الخلاصة:** 41 إثباتاً وقياساً تُشغَّل بأمر واحد على .NET 10 + SQLite + PostgreSQL 16،
> تُثبت مخزناً محلياً دائماً، وبروتوكول مزامنة يستأنف بعد القتل في منتصفه، وحصانة تكرار
> **مستقلة عن الترتيب**، ومديات ترقيم لا تتصادم، وسلوكاً محدّداً لانحراف الساعة وللتعارضات.
> **التصميم الكامل وأوضاع الفشل وكتاب التشغيل في [DESIGN.md](DESIGN.md) (بالعربية).**

> **تحفّظ تنظيمي:** كل ما يخصّ هيئة الزكاة والضريبة والجمارك هنا **غير مُتحقَّق منه** —
> موقع الهيئة محجوب عن هذه الشبكة. لم تُخترع أسماء حقول ولا نقاط نهاية ولا رموز أخطاء.
> نافذة الإبلاغ ٢٤ ساعة **سقف عمل قابل للضبط**، لا ثابت في الكود.

## 1. التشغيل بأمر واحد / one command

```bash
./run.sh                # كل الأقسام (1–7)، نحو 2.5–3 دقائق
./run.sh --only=3       # قسم واحد
./run.sh --only=1234    # عدّة أقسام
```

يخرج برمز `0` فقط عند نجاح كل الإثباتات.

### المتطلبات

- .NET SDK 10.0.x
- PostgreSQL 14+ (طُوِّر واختُبِر على 16.13)

**لا توجد أي كلمة مرور في هذا المستودع.** الاتصال من متغيّر بيئة، وله افتراضي محلي بلا كلمة مرور:

| المتغيّر | الافتراضي |
|---|---|
| `BABEL_POSSPIKE_ADMIN_DB` | `Host=127.0.0.1;Port=5432;Database=babel_posspike;Username=postgres` |
| `BABEL_POSSPIKE_DEVICE_DIR` | `$TMPDIR/babel-pos-devices` (خارج المستودع دائماً) |

التجربة تنشئ قاعدة `babel_posspike` إن لم تكن موجودة، ثم **تحذف وتعيد إنشاء** المخططين
`pos` و`ledger` في كل تشغيلة. استخدم قاعدة مخصّصة للتجارب.

## 3. الشكل باختصار

```
الجهاز (SQLite، ملف واحد)                     الخادم (PostgreSQL، بلا Marten)
─────────────────────────                     ────────────────────────────────
device_counter   عدّاد بلا فجوات               pos.number_range      EXCLUDE USING gist
number_range     المدى الممنوح                 pos.number_gap_assertion  الفجوة تُثبَت إيجاباً
sale             مختوم، بسلسلة SHA-256         pos.sale_inbox        PK = مفتاح حصانة العميل
sale_line        وحدات صغرى INTEGER            pos.exception_queue   ما يحتاج إنساناً
journal_line     شق الإيراد فقط                ledger.journal_entry  دفتر لكل جهاز + سلسلة
sync_checkpoint  مرساة زمن الخادم              ledger.journal_line   NUMERIC(19,4)
uptime_ledger    زمن رتيب عبر الإقلاعات        pos.forbidden_balance التصميم المحظور، للتوثيق
clock_event      شذوذ زمني مُسجَّل إيجاباً
```

الملفات:

```

```

## 4. ما يُعاد استعماله من `spikes/relational-stack`

هذه التجربة **تبني على** الحكم السابق ولا تعيد كتابته:

- شكل دفتر الأستاذ (`journal_entry` / `journal_line`)، والعدّاد بلا فجوات بدل `SEQUENCE`،
  والمشغّل المؤجّل الذي يعمل عند `COMMIT`.
- قواعد التوحيد القياسي في `Support/Canonical.cs` (مقياس ثابت، UTC، ترتيب حقول ثابت، NFC)،
  **مع قاعدة خامسة يفرضها العمل دون اتصال:** القصّ إلى الميكروثانية على الجهاز قبل التجزئة.
- القرار بإسقاط Marten: لا حزمة Marten في شجرة الاعتماديات هنا كذلك.
- القاعدة 1 من `docs/analysis/02-architecture.md`: كل ما يجري داخل قفل العدّاد يقع في
  **نداء خادم واحد** — هنا دالة `pos.post_entry` في PL/pgSQL.
