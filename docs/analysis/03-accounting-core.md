# النواة المحاسبية

## 1. الكيانات الأساسية

```
Organization  المجموعة
  └─ Company  الشركة ──────── FiscalYear ─── FiscalPeriod   السنوات والفترات المالية
       ├─ Branch      الفرع
       ├─ CostCenter  مركز التكلفة (شجرة)
       ├─ Project     المشروع (مركز ربح وتكلفة)
       ├─ Warehouse   المستودع
       └─ Account     دليل الحسابات (شجرة)

JournalEntry  القيد
  ├─ رأس:  رقم · تاريخ · نوع · مرجع · بيان · حالة · مستند مصدر · منشئ · معتمِد
  └─ سطر:  حساب · مدين · دائن · عملة · سعر صرف · مبلغ بعملة الشركة
           · فرع · مشروع · مركز تكلفة · بيان السطر · حساب ضريبي · نسبة ضريبة
```

## 2. حالات القيد

```
مسودة ──▶ مرسل للمراجعة ──▶ معتمد ──▶ مُرحَّل ──▶ (مقفل بإقفال الفترة)
   │              │                        │
   └──▶ ملغى      └──▶ معاد للتعديل        └──▶ معكوس (بقيد مضاد جديد)
```

**القاعدة الحديدية:** بعد `مُرحَّل` لا تعديل ولا حذف. التصحيح بقيد عكسي، ويبقى الأصل ظاهراً في الدفتر.

## 3. دليل الحسابات

الهيكل المقترح للترقيم (خمسة مستويات، قابل للتعديل بعد مراجعة الدليل القائم لدى الشركة) موصوف في
[chart-of-accounts.md](../reference/chart-of-accounts.md).

خصائص كل حساب:

| الخاصية | الغرض |
|---|---|
| `code`, `name_ar`, `name_en` | التعريف |
| `parent_id` | الشجرة |
| `type` | أصول / خصوم / حقوق ملكية / إيرادات / مصروفات |
| `nature` | مدين / دائن (الطبيعة الافتراضية) |
| `is_postable` | هل يقبل الترحيل المباشر؟ (الحسابات التجميعية = لا) |
| `requires_cost_center` | إلزام مركز تكلفة على السطر |
| `requires_project` | إلزام مشروع على السطر |
| `subledger_type` | عميل / مورد / موظف / أصل / بنك / لا شيء — يربط الحساب بدفتر مساعد |
| `currency` | إن كان الحساب بعملة محددة (حساب بنكي بالدولار مثلاً) |
| `is_active` | التعطيل بدل الحذف |

**قاعدة:** لا يُحذف حساب عليه حركة — أبداً. يُعطَّل فقط.

## 4. مصفوفة الترحيل

المخرج التحليلي الأهم. لكل مستند تشغيلي: القيد الذي يولّده بالضبط، ومتى، وكيف يُعكس.

مسودة أولية للنقاش في [posting-matrix.md](../reference/posting-matrix.md).

**تصميم المحرك المقترح:** قوالب ترحيل مخزّنة كبيانات لا ككود.

```
PostingTemplate
  ├─ document_type          نوع المستند المُطلِق
  ├─ trigger_event          عند الاعتماد / عند الاستلام / عند الدفع / دوري
  └─ lines[]
       ├─ account_resolver  ثابت / من إعداد الصنف / من إعداد العميل / من إعداد المشروع
       ├─ side              مدين / دائن
       ├─ amount_source     الإجمالي / الصافي / الضريبة / المحتجز / نسبة من حقل
       └─ scope_resolver    من أين يأتي الفرع والمشروع ومركز التكلفة
```

الفائدة: تعديل قاعدة ترحيل = تعديل صف في جدول، لا تعديل كود ونشر إصدار.

## 5. الضريبة

- كل صنف/خدمة/بند له **تصنيف ضريبي**: خاضع ١٥٪ / صفري / معفى / خارج النطاق
- كل مستند يدعم طريقتي احتساب: **المبلغ شامل الضريبة** أو **غير شامل** (كما في نموذج الواجهة المقدّم)
- التقريب: على مستوى **السطر** ثم الجمع — لا العكس، وإلا ظهرت فروق هللات لا تُطابِق الإقرار
- ضريبة المدخلات وضريبة المخرجات في حسابات منفصلة، ويُنشأ قيد تسوية عند إعداد الإقرار
- تقرير الإقرار الضريبي يُبنى من حركات هذين الحسابين، ويجب أن **يُطابق** مجموع الفواتير المرسلة لـ ZATCA

## 6. العملات

- عملة الشركة (SAR) + عملات الحركة
- كل سطر قيد يخزّن: المبلغ بعملة الحركة + سعر الصرف + المبلغ بعملة الشركة
- **إعادة تقييم الأرصدة بالعملات الأجنبية** في نهاية الفترة → فروق عملة محققة وغير محققة
- جدول أسعار صرف تاريخي (سعر لكل تاريخ)، مع مصدر السعر موثّقاً

## 7. الفترات المالية والإقفال

```
مفتوحة ──▶ مقفلة مؤقتاً (لا ترحيل، والفتح بصلاحية) ──▶ مقفلة نهائياً (لا فتح إطلاقاً)
```

**الإقفال السنوي:** ترحيل أرصدة الإيرادات والمصروفات إلى الأرباح المبقاة، وتوليد قيود افتتاحية للسنة الجديدة.
يجب أن يكون **قابلاً للإعادة** طالما لم تُقفل السنة الجديدة نهائياً — لأن التسويات المتأخرة من المدقق أمر شائع.

## 8. الدفاتر المساعدة (Subledgers)

كل دفتر مساعد يجب أن **يطابق** حسابه في دفتر الأستاذ العام في أي لحظة:

| الدفتر | الحساب المقابل | تقرير المطابقة |
|---|---|---|
| العملاء | الذمم المدينة | أعمار الديون = رصيد الحساب |
| الموردون | الذمم الدائنة | أعمار الديون = رصيد الحساب |
| المخزون | مخزون البضاعة | تقييم المخزون = رصيد الحساب |
| الأصول الثابتة | الأصول ومجمع الإهلاك | سجل الأصول = رصيد الحسابات |
| الموظفون | الرواتب المستحقة والسلف | كشف الذمم = رصيد الحساب |

**اختبار آلي مقترح:** وظيفة تشغَّل يومياً تتحقق من تطابق كل دفتر مساعد مع حسابه، وتنبّه فوراً عند أي فرق.
هذا الاختبار وحده يكشف معظم أخطاء الترحيل قبل أن تتراكم.

## 9. الاختبارات المحاسبية الآلية

لكل صف في مصفوفة الترحيل، اختبار آلي يتحقق أن السيناريو يولّد القيد المتوقع بالضبط:

- فاتورة مبيعات شاملة الضريبة ← قيد صحيح بالضريبة المحسوبة بالاستخلاص
- فاتورة مبيعات غير شاملة ← قيد صحيح
- إشعار دائن جزئي ← عكس جزئي صحيح
- مستخلص مقاول باطن مع محتجز واسترداد دفعة مقدمة ← كل الأطراف صحيحة
- إغلاق وردية POS بطرق دفع متعددة وعجز صندوق ← قيد صحيح
- استحقاق إيجار شهري من دفعة سنوية مقبوضة مقدماً ← استنفاد صحيح
- إهلاك شهري ← قيد صحيح
- إعادة تقييم عملة أجنبية ← فروق صحيحة

**مبدأ:** لا يُقبل دمج (Merge) أي تغيير يمس منطق الترحيل دون اختبار يغطيه.
