## مخطط الحدث

### الحقول على مستوى الحدث

| الحقل | الغرض |
|---|---|
| `event_code` | `<وحدة>.<كيان>.<فعل>` — فريد على مستوى المصفوفة كلها |
| `name_ar` · `name_en` | إلزاميان |
| `module` · `status` · `source_ref` | الوحدة · `drafted` أو `proposed` · مرجع الوثيقة |
| `trigger` | **متى يُرحَّل بالضبط** — لا «عند الاعتماد» المبهمة |
| `precondition` | شرط وجود الحدث أصلاً (نموذج الملكية، الجرد المستمر، أسلوب الفوترة) |
| `reversal` | **كيف يُعكس** — القيد المرحَّل لا يُعدَّل ولا يُحذف |
| `posts_entry` | `false` تعني **لا قيد وهذا بيان سياسة محاسبية** لا إغفال |
| `caveats` | التحفّظات المنقولة من وثائق التحليل — `⚠️` تعني تحفظاً لم يُرفع |
| `amounts` | مفردات المبالغ، ولكل مبلغ `derivation_ar` و`derivation_en` يقول **من أين يأتي** |
| `identities` | علاقات تعريفية بين المبالغ يضمنها المحرك — تُستخدم لإثبات التوازن |
| `conditions` | الحالات التي تغيّر شكل القيد، ولكل شرط تعبير |
| `scenarios` | **تعداد صريح لكل حالة ممكنة** — عليها يقوم إثبات التوازن |
| `lines` | سطور القيد مرتَّبة |

### الحقول على مستوى السطر

| الحقل | الغرض |
|---|---|
| `line_no` | الترتيب |
| `line_kind` | `role` · `sweep` · `import` · `manual` · `mirror` |
| `role` | **الدور — لا رمز الحساب أبداً** |
| `qualifier_source` | من أين يأتي المؤهل: `document.x` أو `line.x` أو `constant:x` أو `null` |
| `side` | `debit` أو `credit` (أو `mirror` لسطر العكس) |
| `amount` | تعبير خطي على متغيرات `amounts` |
| `dimensions` | الأبعاد الإلزامية على هذا السطر — يجب أن تغطي ما يفرضه الحساب |
| `subledger` | الدفتر المساعد، أو `resolved` حين يعتمد على المؤهل وقت التشغيل |
| `when` | الشرط الذي يجعل السطر ينشأ أصلاً — `null` = دائماً |
| `sweep` | محدِّد السطور للأنواع غير `role` |
| `note_ar` · `note_en` | ملاحظة المراجع |

### أنواع السطور غير `role`

| النوع | المعنى | المحدِّد |
|---|---|---|
| `sweep` | المحرك يُعدّد الحسابات المطابقة وينشئ سطراً لكل منها | `account_class` · `foreign_currency_balances` |
| `import` | سطر لكل صف في ملف مستورد | `imported_opening_lines` |
| `manual` | سطور أدخلها المستخدم | `operator_entered_lines` |
| `mirror` | سطر مقابل لكل سطر في القيد المصدر بالطرف المعاكس | `source_entry_lines` |

كل محدِّد يحمل `postable_only: true` إلزاماً: لا يختار حساباً تجميعياً أبداً.

## كيف يُثبت التوازن جبرياً

هذا أهم ما في التصميم. تعبير المبلغ يُحلَّل إلى **تركيبة خطية** من متغيرات المبالغ، ثم لكل سيناريو:

```
1) صفِّر كل متغير في zero_amounts للسيناريو
2) عوّض identities (الحدث ثم السيناريو) حتى الاستقرار
3) احسب: مجموع(المدين) − مجموع(الدائن)
4) يجب أن تكون النتيجة الصفر المطلق — كل معامل صفر والثابت صفر
```

مثال — فاتورة إيجار لوحدة تجارية:

```
مدين  1310 المستأجرون          net + tax
دائن  2171 إيرادات مؤجلة       net
دائن  2131 ضريبة مخرجات        tax        (when: unit_is_vat_taxable)
                               ───────────
(net + tax) − net − tax  =  0   ✓
```

وللوحدة السكنية المعفاة يسقط سطر الضريبة، ويصفّر السيناريو المتغير `tax`:

```
(net + 0) − net  =  0   ✓
```

ولو نسي كاتب القاعدة تصفير `tax` في السيناريو المعفى لبقي فرقٌ قدره `tax` **في كل فاتورة سكنية** —
وهذا بالضبط ما ترفضه القاعدة `V03`، ويغطيه اختبار سلبي مخصص في
[`tools/matrix-validator/tests`](../../tools/matrix-validator/tests).

**القيود المفروضة على التعبير عمداً:** لا ضرب متغيرين ببعضهما ولا قسمة على متغير. القسمة والضرب
بثابت فقط. حساب يضرب مبلغين ليس سطر ترحيل، بل حسابٌ يخصّ المستند نفسه. وقاعدة أشدّ منها:
**لا نسبة ضريبة ولا نسبة محتجز ولا حدّ مكتوب في التعبير** — كلها في جداول إعدادات
([CONTRIBUTING §3.6](../../CONTRIBUTING.md)).
